# Seeing macro expansions

## Landed (2026-10-26)

- `#debug` on an invocation (`#debug name(...)`, `#debug $name(...)`,
  `#debug #meta ...`) marks every emission made while evaluating that
  expression `write_out` and prints `#debug emission: <path>` per file;
  `write_emitted_sources` writes them beside the errored ones. `eval_expr` and
  the definition-level metaprogram runner do the marking. `#debug macro` no
  longer parses; macros never carry `CompilerDebug`, so no IR/bc dump.
- Every macro, `#meta` and `configure` emission starts with `// generated by
  <macro name[type args]|#meta block|configure> at <path>:<line>`, then
  `// in <enclosing fn[type args]>` and one `// <param> = <value>` line per
  static macro arg. Module-params emissions (spliced build.k1 source) have none.
- The specialization is in the header on purpose, against this plan's earlier
  body-only hashing: `emitted_parse_cache` keys the whole content, so each
  specialization mints its own file (stdlib `--chatty`: 78 -> 111 emitted).
  A file on disk names the context it ran in, which errors inside generic code
  need.

## Open

### Call site in the diagnostic

A crash inside a macro points at the macro body, and an error that remaps
into the macro's template literal points at the macro definition; neither
names the call site:

```
tmpl.k1:2:2: error
│   macro bad2(pattern: string) {
│ ->  "nonexistent-fn(${core/meta/str-lit(pattern)})"
│     ^^^^^^^^^^^^^^^
│  Function not found: 'nonexistent-fn'
```

`report_ext` remaps the span through the chunk table (`remap_span`, ≤16 hops)
before storing it, so `write_error`'s note block only fires when the span
lands in glue (`code/from-string`, escapes, dedent). `do_with_vm` returns a
crash as an `Err` spanned at the `crash(...)` in the macro body;
`with_bc_trace` (bc/exec.rs) appends the VM stack and is the precedent for
annotating an `Err` as it bubbles.

One helper in typer/report.rs, so `K1Message` stays 16 bytes and the snapshot
format is untouched:

```rust
fn expansion_trail(&self, call_span: Span) -> String
```

returns one line per hop, `\nexpanded from <path>:<line>:<col>`, for
`call_span` and then each enclosing emitted file's `call_span` (same ≤16 walk
as `remap_span`, on `emitted_source_for_file`), each remapped to source.
Appended to `e.message` at:

- the macro arm of `execute_macro_call_body` on the `Err` out of `do_with_vm`
  (the crash wall);
- the `#meta` arm of `compile_static_or_meta`, same;
- `report_ext`: computed from the span before `remap_to_source_span` when
  `emitted_source_for_file` hits, covering the template and glue cases and
  definition-level expansions whose errors surface after
  `compile_emitted_code` returned.

Then delete `write_error`'s note block; it only covered glue. `//errmsg`
matches `expanded from` in the message text. Tests:
`test_src/macro_crash_site.k1` (crash path), `macro_template_site.k1`
(remapped-out path), `macro_emitted_site.k1` (glue path), each
`//errmsg: expanded from`.

### `--dump-emitted`

Writes every emission without marking calls: `write_emitted_sources(&self,
dump_all: bool)` writes when `emitted.write_out || dump_all`; under
`dump_all`, `remove_dir_all` + `create_dir_all` on `config.out_dir_generated`
first, so a dump never sits beside stale serial-numbered files. The
diagnostic and `#debug` paths never clear: `write_emitted_sources` runs in the
LSP (`compile_program_ext`), per keystroke. `Args` gains `dump_emitted: bool`
beside `dump_ir`; the literal `Args` sites get `dump_emitted: false`.
