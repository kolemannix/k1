# Seeing macro expansions

Walls (showcase 04/05/06): `#debug macro` dumps the macro's own IR twice and
its bc, never an expansion;
emitted files reach `.k1-out/generated/` only behind `has_diagnostic`; a crash
inside a macro points at the macro body, never at the call site. Three showcase
sections work around it by printing `define-impl(...).text()` from a `#static`
block (05-macros.md:288, :447; 06-regex.md:60).

## What is there today (measured 2026-09-21)

`read_emitted_code_raw` (static_exec.rs:1132) hands the VM's `code` chunks to
`build_emitted_source` (:1162), which writes a `// generated by #meta block at
<file>:<line>` header, wraps expression output in `{ }`, concatenates the
chunks, and records each chunk's byte range against its source span
(`CodeChunkPos`, typer.rs:2711). `compile_emitted_code` (:1220) hashes the
content, probes `emitted_parse_cache` keyed `(hash, span)` (:1241), then
registers the string as a real `SourceFile` at
`.k1-out/generated/meta_<stem>_<line>_<serial>.k1` (:1257) and parses it.
Spans in emitted code are real spans into an in-memory file; error rendering
prints the emitted text inline whether or not the file exists on disk.

`report_ext` (typer/report.rs:226) remaps the span through the chunk table
(`remap_span`, :180, ≤16 hops) before storing it, so `write_error`'s note block
(:311-315) only fires when the span lands in *glue* (text from
`code/from-string`, escapes, dedent). When the span remaps into the macro's
template literal, the box points at the macro definition and the call site is
silently lost:

```
tmpl.k1:2:2: error
│   macro bad2(pattern: string) {
│ ->  "nonexistent-fn(${core/meta/str-lit(pattern)})"
│     ^^^^^^^^^^^^^^^
│  Function not found: 'nonexistent-fn'
```

The crash wall is the same plumbing from the other side: `do_with_vm` (:236)
returns the crash as an `Err` whose span is the `crash(...)` call in the macro
body; `with_bc_trace` (bc/exec.rs:184) appends the VM stack, and nothing
appends the typer-level fact that `shout("")` at probe6.k1:8 was being
expanded. Errors are created with `make_error` (report.rs:135) and reported
only when they reach a `report` call, so annotating an `Err` as it bubbles is
sound; `with_bc_trace` is the precedent.

Volume, `--chatty --no-cache check`: suite1 16 emitted / 3 kb, httpapp
43 / 9 kb, stdlib 11 / 6 kb, refchess / brotli / selfhost 1 each.

Four findings that shape the answer:

1. **`write_emitted_sources` (static_exec.rs:1304) runs in the LSP.** Its
   caller, compiler.rs:1508, is inside `compile_program_ext`, which
   `lsp_main.rs:391,548` and `lsp_support.rs:624` call. The `has_diagnostic`
   gate stays; anything that writes or clears the dir unconditionally would run
   per keystroke.
2. **The gate is already the right predicate** for the diagnostic path: the
   emitted file's path is printed in the error box, so the file exists exactly
   when something names it.
3. **Expression-level `#debug` is now a hint, not a log level.** `eval_expr`
   (typer.rs:6700) reads `self.ast.exprs.is_debug(expr_id)` and, after
   evaluation, `report_hint`s `DEBUG COMPILE DONE` with the typed result. For
   `#debug shout("hi")` that already shows the *typed* expansion
   (`println(.{ filename: ..., line: 2u32, ... }, "hi")`); what is missing is
   the emitted *text*, and the `#debug macro` form prints nothing of the sort.
   `#debug macro foo` today: `is_function_concrete=` (typer.rs:4662), the IR
   unit (ir.rs:1567 -> :1625), the optimized IR again (:1679), and the bc
   disassembly (bc/lower.rs:645, same `is_debug`).
4. `nearest_parent_function(ctx.scope_id)` (scopes.rs:1425) already answers
   "what were we compiling": specialized bodies get
   `ScopeOwnerId::Function(specialized_id)` at typer.rs:13068, and
   `function_id_to_string(f, false)` renders `fn scan[t := string](...)` from
   `specialization_info` (dump.rs:588-596). No new plumbing. The work-stack
   trace is not usable: `Trace::push` (trace.rs:411) returns `None` for
   non-essential kinds unless profiling or a live progress sink, and
   `FunctionSpecialize`/`MacroCall`/`FunctionTypecheck` are non-essential
   (`is_essential`, :151), so the stack is empty in a normal compile.

## Recommendation

Keep files as the errored-expansion artifact; make the live cases inline.

### 1. `emitter: Option<FunctionId>` threaded into `compile_emitted_code`

`None` for `#meta` blocks (static_exec.rs:1124), `Some(function_id)` from
`run_macro_and_compile_output` (:1509), which already holds the *specialized*
macro id. One caller (:1492) is untouched.

### 2. A real header, built where the context is

Move header construction out of `build_emitted_source` (delete the `writeln!`
at :1177-1183 and its `get_span_location`/capacity fiddling; it returns the
body with body-relative offsets) into `compile_emitted_code`, which has `ctx`
and `emitter`. Header:

```
// emitted by macro regex/define
// at showcase/re.k1:29:12
```

built from `emitter` (`function_id_to_string`) + a small
`span_location_string(span) -> "path:line:col"` helper on `TypedProgram`
(column = `span.start - line.start_char`, as `write_source_location`,
parse.rs:1968, computes it) that §3 and §4 reuse. Shift each `CodeChunkPos` by
`header.len()` before pushing `EmittedSource`. Rename the file
`<macro-name>_<stem>_<line>_<serial>.k1` (`meta_...` for `None`) so the dir
greps. Delete the TODO at :1250-1252.

**The specialization context does not go in the header.** The parse cache
short-circuits at :1241 before any file is created; if the header carried
`fn scan[t := string]`, every specialization would miss the cache and mint its
own file. A file on disk is a deduped artifact and can only honestly carry the
facts constant across the hits: emitter and call site. Hash the **body** only
(build the header after the cache probe, so a hit costs nothing). Per-expansion
facts go in §3 and §4, where they are always accurate. Per-specialization files
would be a one-line flip (hash header+body) with the file count as the price;
not the default.

### 3. `#debug` prints each expansion

Add `EvalExprFlags::Debug = 1 << 9` (typer.rs:328-352; bits 0-8 used). In
`eval_expr` (:6700), when `is_debug`, evaluate the inner expr with
`ctx.with_debug()`; nested expressions, including the emitted expression that
`compile_emitted_code` evaluates with the same `ctx` (:1292), inherit it. No
`TypedProgram` field, nothing for `snapshot.rs`.

In `compile_emitted_code`, after the cache probe and before parsing, when
`ctx.is_debug()` or `emitter.is_some_and(|f| self.get_function(f).compiler_debug())`,
`report_hint(span, ...)` with:

```
expansion of macro regex/define
  while compiling fn scan[t := string]

<emitted text>
```

`report_hint` draws the box at the call site, exactly like the existing
`DEBUG COMPILE DONE` hint, and its dedup (`report_ext`, :234) collapses only
identical (message, span) pairs; the "while compiling" line makes each
specialization distinct. `#debug shout("hi")` then prints the emitted text
followed by the existing typed-result hint. The line comes from
`nearest_parent_function(ctx.scope_id)` + `function_id_to_string(f, false)`,
omitted when there is no enclosing function (top-level `$define`).

Guard the IR/bc dump for macros: ir.rs:1567 `let is_debug =
f.compiler_debug() && !f.is_macro();` — `bc/lower.rs:645` keys off the same
flag through `finalize_unit`, so one edit silences both. `--dump-ir` still
covers a macro's IR when someone wants it. That noise is why the wall reads
"prints IR/bc, not the expansion".

### 4. Call site in the diagnostic

One helper in typer/report.rs, modelled on `with_bc_trace` so `K1Message`
stays 12 bytes and the snapshot format is untouched:

```rust
fn expansion_trail(&self, call_span: SpanId) -> String
```

returns one line per hop, `\nexpanded from <path>:<line>:<col>`, for
`call_span` and then each enclosing emitted file's `call_span` (same ≤16 walk
as `remap_span`, :180, on `emitted_source_for_file`), each location remapped to
source. Appended to `e.message` at:

- `run_macro_and_compile_output` (:1503-1508) on the `Err` out of `do_with_vm`
  — the crash wall (probe6: box at `crash(...)`, trail names `probe6.k1:8:2`).
- the `#meta` arm (:1111-1123), same.
- `report_ext` (:226): computed from the span **before** `remap_to_source_span`
  when `emitted_source_for_file` hits — covers the template case (box on the
  literal, trail names the call) and the glue case, and definition-level
  expansions whose errors surface long after `compile_emitted_code` returned.

Then delete `write_error`'s note block (:311-315): it only covered glue.
`//errmsg` keeps working: substring match against the message text, which now
contains `expanded from`.

### 5. `--dump-emitted`

`#debug` requires editing the macro definition, which you cannot do for a
macro in `modules/core` or a dependency. `write_emitted_sources(&self,
dump_all: bool)`: write when `emitted.has_diagnostic || dump_all`; under
`dump_all`, `remove_dir_all` + `create_dir_all` on `config.out_dir_generated`
first, so a dump never sits beside stale serial-numbered files from an earlier
run. The diagnostic path never clears (finding 1). `Args` gains
`dump_emitted: bool` beside `dump_ir` (compiler.rs:334); the call becomes
`k1.write_emitted_sources(args.dump_emitted)` (:1508); five literal `Args`
sites get `dump_emitted: false`: compiler.rs:2322, lsp_main.rs:369, :532,
test_suite.rs:118, lsp_support.rs:610. No `CompilerConfig` field.
